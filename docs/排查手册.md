# 排查手册（一页）

改代码出问题，按这个顺序来，不靠猜。

## 1. 打开错误浮层

- 出错后页面**右上角出现红色数字徽标**，点它；或随时按 **`Ctrl+Shift+E`**
- 每条记录 = `✖ 未捕获异常` / `◆ console.error` / `· 轨迹点`
- 点一条记录，下方给出：**出处文件、行号:列号、完整堆栈**

## 2. 读一条错误

```
✖ [14:02:11] Cannot read properties of null (reading 'x')   app.js:412:15
```

- `app.js:412:15` — 直接打开对应文件跳到 412 行，别从头猜
- 堆栈里从下往上读：最下面一两行通常是你自己的代码，往上是框架/浏览器内部
- `file://` 下双击打开也能用，不需要开 devtools

## 3. 常见错对照表

| 报错关键词 | 大概率原因 | 去哪看 |
|---|---|---|
| `is not defined` | 变量/函数拼写错，或 script 加载顺序问题 | 出处行号 + `index.html` 底部标签顺序 |
| `Cannot read properties of null/undefined` | 取的 DOM 元素不存在（id 写错、执行时机太早） | 出处行号，确认 `getElementById` 的 id |
| 改了代码页面没变化 | **浏览器缓存**——改了 js/css 忘更新 `index.html` 里的 `?v=` 日期戳 | 对应 `<script>/<link>` 行的 `v=` |
| `QuotaExceeded` / `localStorage` | 存储满了或隐私模式限制 | `backup.js` 的导入/回滚逻辑 |
| 练习场里 Python 报错 | 那是**学员代码**的真实报错，不是应用坏了 | 练习场输出区；回归跑 `tools/pyexec-regression.test.js` |
| `node --test` 挂了 | 改破了行为 | 看失败用例名，对应到具体模块 |

## 4. 排查纪律

1. **先复现**：能让它再错一次，才有得看；复现不了先加 `__devOverlay.mark('关键步骤')` 留轨迹
2. **看浮层定位**到 文件:行号，读代码 + 最近一次的 git 提交（`git log -p -1`）
3. 修之前跑 `node --test` 记录基线，修完再跑必须全绿
4. 一次只修一个错；提交信息写清楚"错因"，不只写"修复"
5. 清单外的发现（顺手看到的别的问题）**记下来先不修**，另开工单

## 5. 浮层本身出问题？

浮层是 `dev-overlay.js`，零依赖单文件。要临时禁用：删掉 `index.html` 里它那一行 `<script>` 即可。
